# AWP advancement (All Weather Portfolio)

This folder contains our All Weather Portfolio (AWP) replication and enhancement work. It includes:
- a **replication + diagnostics notebook** on the core AWP universe
- a **strategy-variant comparison notebook** (core vs BTC vs SVXY; different rebalance frequencies)
- the **input datasets** used by both notebooks

## Notebooks

### `awp_replication_analysis.ipynb` (replication + evaluation)

**Universe (core 5):** `SPY`, `TLT`, `IEF`, `GLD`, `DBC`  
(The data file also contains `BTC` and `SVXY`, but the replication section focuses on the core 5.)

#### What it does
- **0) Load data**
  - Reads `FINA4359 database +btc.csv`, parses `time`, and constructs daily returns.
- **1) Replication: fixed inverse-vol**
  - Computes full-history annualized vol for each core asset and sets **inverse-vol weights**.
  - Produces a table with:
    - Full-history annual SD
    - Portfolio weight (inverse-vol normalized)
    - “Assigned vol” contribution (vol × weight)
- **2) Performance table & growth of $1**
  - Compares **AWP vs Market (S&P 500 / SPY)**:
    - Summary statistics table
    - Growth of \$1 plot (dual-axis: market vs AWP)
    - Drawdown chart
- **Diagnostics**
  - **Correlation**: rolling (252d) average pairwise correlation across the 5 assets.
  - **PCA**: rolling (252d) PC1 share of total variance and PC1 weights (via eigen-decomposition).
- **Factor regression**
  - Loads **Fama–French 5 factors + Momentum** (Ken French data library) and runs factor analysis on AWP returns (requires `statsmodels`).
- **Macro / “seasonal sensitivity”**
  - Reads `macro_data.csv` (Inflation, Growth), converts to % changes, and runs regressions of monthly returns vs macro changes.
  - Outputs coefficient tables with significance stars (***, **, *).

#### Main outputs
- Inverse-vol weight table for the core 5
- AWP vs market performance comparison (stats + cumulative wealth + drawdown)
- Rolling correlation and PCA diagnostics
- FF5+Mom regression results
- Macro sensitivity regression results

### `FINA4359.ipynb` (strategy variants + rebalancing comparison)

This notebook is the “main” analysis used to compare different AWP variants and rebalancing frequencies.

#### What it does
- **(Optional) Data refresh via yfinance**
  - `update_database()` downloads total-return (auto-adjusted) prices from `yfinance` starting `2011-08-18` for:
    - Core: SPY, GLD, DBC, IEF, TLT
    - Extensions: BTC (`BTC-USD`), short vol (`SVXY`)
  - Saves the result as `FINA4359 database +btc.csv`.
- **Static weighting comparison (illustrative)**
  - Computes full-sample annualized vol and compares:
    - **Typical Dalio weights** (fixed): 30% SPY, 40% TLT, 15% IEF, 7.5% GLD, 7.5% DBC
    - **Inverse-vol (risk parity) weights** on:
      - core only
      - core + SVXY
  - Plots growth of \$1 across these static variants.
- **Dynamic “risk parity” backtest (inverse-vol, rebalanced)**
  - Implements `backtest_risk_parity(...)`:
    - **Start date**: Jan 2015 (uses **2014 returns as the initial volatility seed**)
    - **Lookback**: 252 trading days (for subsequent rebalances)
    - **Rebalance frequencies**: Monthly (`M`), Half-yearly (`6M`), Annual (`Y`)
  - Runs the backtest across universes:
    - Core
    - Core + BTC
    - Core + SVXY
    - Core + BTC + SVXY
  - Builds a comparison plot: “All-Weather Portfolio Variants (2015–2026)”.
  - Computes a metrics table per strategy:
    - Total return, CAGR, Vol, Sharpe (using rf_rate=4.28), Max drawdown

#### Main outputs
- Growth-of-\$1 comparison across universes and rebalance frequencies (2015–2026)
- Summary table of performance metrics (sorted by Sharpe in the notebook)

## Data files
- `FINA4359 database +btc.csv`
  - Price database used by both notebooks (generated by `update_database()` or provided as-is).
  - Contains columns for core assets plus BTC and SVXY.
- `macro_data.csv`
  - Macro series used in `awp_replication_analysis.ipynb` for Inflation/Growth sensitivity.

## How to run (recommended)
1. Open these notebooks from **this folder** so relative paths work.
2. Run `FINA4359.ipynb` first if you want the end-to-end variant comparison and/or to regenerate `FINA4359 database +btc.csv` using `yfinance`.
3. Run `awp_replication_analysis.ipynb` for the replication writeup and additional diagnostics (PCA, FF regressions, macro sensitivity).

## Environment notes
- Typical Python stack: `pandas`, `numpy`, `matplotlib`, `yfinance`.
- `awp_replication_analysis.ipynb` will also use `statsmodels` if installed (for regressions). If it’s missing, regression sections may be skipped or error depending on your environment.
